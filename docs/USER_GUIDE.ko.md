# Shellground 사용설명서

## 1. 처음 실행하기

[README의 운영체제별 설치 방법](../README.md)을 먼저 따라 프로그램을 실행합니다. Python에서 소스로 실행하거나, 해당 운영체제에서 빌드한 실행 파일을 사용합니다.

1. Docker가 실행 중인지 확인합니다. Windows에서는 Docker Desktop의 Linux containers 모드가 필요합니다.
2. 프로그램 상단의 **실행 환경 확인**을 누릅니다.
3. 이미지가 없다는 안내가 나오면 **최초 실습 환경 준비 (인터넷 필요)**를 누릅니다. 확인 창을 승인하면 Ubuntu와 실습 도구를 내려받아 이미지를 만듭니다.
4. 하단 상태 표시줄에서 진행 상황을 확인합니다. 최초 준비가 끝나면 이후 실습에는 외부 인터넷이 필요하지 않습니다.
5. 첫 단원의 설명을 읽고 **예시 실습 시작**을 누릅니다.

프로그램 준비 중에는 관련 버튼이 잠깁니다. 환경 준비·채점 중에는 작업이 끝난 뒤 창을 닫아 주세요.

## 2. 화면 읽기

- **왼쪽 단계 목록**: 4개 난이도, 13개 단원. 완료·학습 가능·잠김을 표시합니다.
- **상단 진도**: 활용 문제 2개를 통과한 단원 수입니다. 예시만 따라 했다고 완료 처리하지 않습니다.
- **설명/문제 영역**: 현재 시작 위치와 달성해야 할 목표를 표시합니다. 내용이 길면 영역 안에서 스크롤하세요.
- **검은 터미널**: 명령을 실제 Linux에서 실행하는 곳입니다. 먼저 클릭해 입력 초점을 주세요.
- **채점 결과**: 목표의 각 조건을 통과/미완료로 나누어 표시합니다.

## 3. 단계별 학습

### 새 명령 배우기

용도와 주요 옵션을 읽습니다. `-R`과 `-r`, `curl -o`와 `wget -O`처럼 대소문자가 다른 옵션을 구분하세요.

### 예시 직접 실습

문제 아래에 따라 입력할 예시가 나옵니다. 한 줄씩 입력하고 Enter를 누르세요. 명령 실행이 끝나 프롬프트가 다시 표시되면 **결과 채점** 또는 **F5**를 누릅니다. 성공하면 **다음 문제**로 이동합니다.

### 활용 문제

정답은 숨기고 목표만 표시합니다. 시작 위치·대상 경로·파일 이름이 바뀌므로 이전 예시를 그대로 입력하면 실패할 수 있습니다. 조건을 읽고 직접 명령을 조합하세요. 2개 문제를 통과하면 단원이 완료되고 다음 단원이 열립니다.

틀렸다고 바로 초기화되지 않습니다. 터미널에서 현재 결과를 확인하고 수정한 뒤 다시 채점하세요. **힌트**는 풀이 방향을 알려 줍니다.

### 배운 범위 올랜덤

단원을 하나 이상 완료하면 왼쪽 아래 **배운 범위 올랜덤**이 열립니다. 완료한 단원 전체에서 새로운 경로·파일 조건을 생성합니다. 미학습 단원은 출제하지 않습니다. 후반 단원의 문제는 다운로드와 압축 해제 또는 권한 설정처럼 여러 기술을 함께 사용합니다.

## 4. 기본 키 조작

| 키/동작 | 기능 |
| --- | --- |
| Enter | 명령 실행 |
| Tab | bash의 명령·경로 자동 완성 |
| ↑ / ↓ | 실행한 명령 기록 탐색 |
| Ctrl+C | 실행 중인 명령 중단 |
| Ctrl+L | 화면 정리; 파일이나 작업 결과는 삭제하지 않음 |
| F5 | 현재 결과 채점 |
| 마우스 드래그 → Ctrl+Shift+C | 선택한 터미널 내용 복사 |
| Ctrl+Shift+V / 우클릭 붙여넣기 | 클립보드 내용 붙여넣기 |
| Shift+PageUp / Shift+PageDown, 휠 | 출력 기록 스크롤 |

붙여넣은 여러 줄은 bash의 bracketed paste 상태에 따라 입력 편집 상태로 놓일 수 있습니다. 내용을 확인하고 Enter를 눌러 실행하세요. `exit` 또는 Ctrl+D로 셸을 종료했다면 **문제 다시 시작**으로 다시 열 수 있습니다.

## 5. 예제: 다른 위치의 전체 목록을 파일로 저장

다음은 설명용 경로입니다. 실제 문제에 표시된 경로와 파일명으로 바꿔 입력하세요. 보고서 저장 폴더는 실습에서 준비합니다.

목표: `/home/learner/data/release4242`의 숨김 항목과 하위 폴더를 상세 형식으로 조사해 `/home/learner/reports/inventory-4242.txt`에 저장.

```sh
pwd
ls -alR /home/learner/data/release4242 > /home/learner/reports/inventory-4242.txt
cat /home/learner/reports/inventory-4242.txt
```

- `-a`: `.env` 같은 숨김 항목과 `.`·`..`도 포함.
- `-l`: 권한, 소유자, 크기, 시간 등 상세 정보.
- `-R`: 하위 디렉터리까지 재귀 조회. 소문자 `-r`과 다릅니다.
- `>`: 표준 출력을 파일에 저장. 기존 내용이 있으면 덮어씁니다.

다음처럼 이동 후 실행해도 같은 목록 결과이면 인정합니다.

```sh
cd /home/learner/data/release4242
ls -laR > /home/learner/reports/inventory-4242.txt
```

파일명만 맞거나 목록 일부만 있으면 통과하지 않습니다. 대상 원본을 삭제해서 목록을 줄여도 인정하지 않습니다. 채점은 준비된 원래 목록을 기준으로 합니다.

## 6. 예제: 다운로드와 파일 형식

문제에 나온 URL과 저장 경로를 사용하세요. 다음은 curl 단원의 설명용 예시입니다.

```sh
curl -fL -o /home/learner/delivery/result4242/received-toolkit.deb http://127.0.0.1:8765/toolkit.deb
```

실습 서버의 `127.0.0.1`은 **컨테이너 내부**입니다. 호스트 브라우저에서 같은 주소가 열리지 않는 것이 정상입니다. 외부 사이트에 접속해 내려받는 문제는 현재 제공하지 않습니다.

| 형식 | 실습 처리 |
| --- | --- |
| `.deb` | `dpkg-deb --info`로 확인, `--extract`로 내용 추출. 관리자 설치는 하지 않음 |
| `.sh` | `cat`으로 내용 확인 → `chmod u+x` → 결과 파일 경로를 인자로 주어 실행 |
| `.tar.gz` | `tar -tzf`로 내용 확인, `tar -xzf 파일 -C 폴더`로 풀기 |
| `.zip` | `unzip -l`로 내용 확인, `unzip 파일 -d 폴더`로 풀기 |

확장자나 파일명만 바꾸면 통과하는 방식이 아닙니다. 다운로드 파일의 바이트와 필요한 압축 해제·스크립트 결과까지 확인합니다. 실제 업무에서는 출처와 내용을 확인하지 않은 스크립트를 실행하지 마세요.

## 7. 채점과 다시 시작

채점은 입력한 명령의 철자를 맞추는 시험이 아닙니다. 목표 파일·내용·권한·현재 위치를 만족하면 다른 도구나 명령 조합도 인정합니다. 따라서 특정 도구를 꼭 사용했는지 감시하는 부정행위 방지 시험은 아닙니다.

**문제 다시 시작**, 다른 단계 전환, 다음 문제 이동은 해당 문제의 임시 파일을 버리고 새 환경을 만듭니다. 복구할 실습 파일이 필요하면 전환 전에 내용을 복사해 두세요. 단원 완료 진도와 임시 실습 파일은 별개입니다.

## 8. 진도와 종료

완료 진도는 Qt의 사용자별 AppDataLocation 아래 `progress-v3.json`에 저장됩니다. Linux에서는 일반적으로 `~/.local/share/Shellground/Shellground/`, Windows에서는 사용자 AppData 영역에 위치하며 환경 설정에 따라 달라질 수 있습니다. 백업하려면 앱 종료 후 해당 파일을 복사하세요.

정상 종료 시 이 앱이 만든 실습 컨테이너만 정리합니다. Docker 이미지 자체와 다른 컨테이너는 삭제하지 않습니다. 강제 종료 뒤에는 다음 명령으로 남은 실습 컨테이너를 확인할 수 있습니다.

```sh
docker ps -a --filter label=com.shellground.owner
```

정리가 필요하면 출력에서 Shellground 실습 컨테이너임을 확인한 **정확한 이름 하나**를 대상으로 Docker의 삭제 기능을 사용하세요. 다른 프로젝트의 컨테이너를 일괄 삭제하지 마세요.

## 9. 자주 생기는 문제

| 증상 | 확인할 내용 |
| --- | --- |
| Docker가 없다는 메시지 | Docker 설치 및 실행 여부와 PATH 확인 |
| daemon 연결/권한 오류 | 현재 사용자로 터미널의 `docker info`가 성공하는지 확인. 앱을 무조건 관리자 권한으로 실행하지 말고 Docker 공식 설치 안내를 따르기 |
| Windows에서 Linux containers 안내 | Docker Desktop을 WSL 2/Linux containers 모드로 전환 |
| 실습 이미지 없음 | 상단 **최초 실습 환경 준비** 실행 |
| 최초 이미지 준비 실패 | 인터넷 연결, Docker 상태, 남은 저장 공간, 하단 오류 메시지 확인 |
| 명령은 실행됐는데 미완료 | 시작 위치, 파일명, 대소문자, 숨김/재귀 옵션, 저장 폴더, 파일 내용 확인 |
| 멈춘 명령 | 터미널에 초점을 주고 Ctrl+C. 셸이 종료되었으면 문제 다시 시작 |
| Linux Qt/xcb 오류 | `libxcb-cursor0` 등 Qt 시스템 라이브러리 확인. Ubuntu 24.04 외 배포판은 별도 호환 확인 필요 |
| 한글이 네모로 보임 | 소스 실행에서는 `desktop/assets/NotoSansCJK-Regular.ttc` 파일 존재 확인. 실행 파일은 글꼴 포함 상태로 다시 빌드 |
| 진도 저장 실패 | 사용자 AppData 저장 공간·쓰기 권한 확인. 오류를 무시하면 재실행 시 진도가 사라질 수 있음 |

문제 보고 시 운영체제, 실행 방법, 앱 버전, 문제 단계와 오류 메시지를 알려 주세요. 비밀번호, 토큰, 개인 파일 내용은 공개 이슈에 올리지 마세요.
