# Shellground Android 4.7.4

브라우저/WebView가 아닌 Android 네이티브 화면과 실제 내장 CPython을 사용합니다. Python 실습에는 PC 연결, 계정, 외부 Python 앱, 네트워크가 필요 없습니다. 앱 안에서 NumPy·Matplotlib·pandas·SciPy·Seaborn·scikit-learn을 실행합니다.

배포 APK는 Python과 실제 Ubuntu ARM64 환경을 함께 포함합니다. 메뉴에서 Linux·Docker·ROS 2, Conda·pip, Jupyter를 선택합니다. PC 연결·Termux·루팅·WSL·외부 실습 서버 없이 앱 안에서 실행하며, 명령 출력이나 커널 실행을 흉내 내는 방식이 아닙니다. 실제 ARM 휴대폰에서의 성능과 모든 과정을 전수 실행한 결과까지 보장한다는 뜻은 아닙니다.

배포 파일은 `../releases/Shellground-4.7.4-Android.apk`입니다(약2.10GB). APK 설치 공간과 별도로 최초 Linux 준비에 약2GB와 실습용 쓰기 공간이 필요합니다. Android 설치기의 임시 공간도 고려해 설치 전 최소10GB 이상 여유 공간을 권장합니다. 개발 서명 APK이며 Play 스토어 배포판은 아닙니다.

## 사용

1. 배포 APK를 기기에 설치합니다. Android에서 해당 파일을 연 앱의 ‘알 수 없는 앱 설치’ 허용이 필요할 수 있습니다. 같은 서명 키의 이전 버전은 업데이트 설치로 진도를 유지합니다. 서명이 다른 과거 시험판에서 업데이트 오류가 나면 무작정 삭제하지 마세요. 앱 삭제는 그 앱의 저장된 진도도 지웁니다.
2. 상단 `단원 선택`에서 분야와 단원을 고릅니다. **배우기 → 예시 → 활용 1 → 활용 2**로 진행하며 상단 막대에 현재 과정이 표시됩니다.
3. `설명 / 코드 / 출력 / 채점` 탭이 같은 넓은 작업 공간을 공유합니다. 설명과 예제 코드를 읽고 `코드`에서 직접 입력하세요. 탭을 바꿔도 입력은 유지됩니다. 아래 `실행`을 누르면 `출력`, `채점`을 누르면 `채점` 탭으로 자동 이동합니다. 미완료 항목은 `코드` 탭에서 이어서 수정할 수 있습니다.
4. 오른쪽 위 `⋮` 메뉴에 힌트·실습 초기화·개념 퀴즈·올랜덤·사용 안내가 있습니다. 읽던 개념 카드·학습 소단계·완료 여부는 자동 저장합니다. 입력 코드·실습 파일·변수는 영구 저장하지 않습니다.
5. `배운 범위 올랜덤`은 활용 1·2를 완료한 범위에서 출제합니다. 메뉴의 `올랜덤 끝내기`로 이전 학습에 돌아갑니다.
6. 종료하거나 다른 앱으로 이동하면 별도 Python 작업 프로세스를 중단합니다. 이때 임시 변수는 사라지며, 다음 실행에서 문제 데이터를 준비합니다. 앱에 외부 출처의 코드를 붙여 넣지 마세요. 파일/네트워크 실수 방지는 있으나 적대적 코드용 보안 VM은 아닙니다.

외부 키보드: Shift+Enter 실행, F1 힌트, F2 초기화, F5 채점, F6 다음. 모바일 화면의 터치 버튼으로도 같은 작업을 합니다.

키보드를 열면 상단 제목을 접어 입력 공간을 확보하고 실행·채점·다음 버튼은 키보드 위에 유지합니다. 작은 화면에서는 부가 상태 표시를 줄이며, 긴 설명과 채점 목록은 독립적으로 스크롤합니다.

## 실제 Linux 이미지 포함판 사용

메뉴의 `Linux · Docker · ROS 2`를 선택한 다음 단원을 고르고 `실습 시작`을 누릅니다. Android9 이상이 필요합니다. 최초 한 번 APK 안의 이미지를 앱 전용 저장소에 준비하며 별도 PC·Termux·루팅·WSL·실습 서버 설정은 필요하지 않습니다. 매 시작 때 이미지 무결성 확인과 실제 OS 부팅이 있어 즉시 준비되는 것은 아닙니다.

`문제·설명 / 터미널 / 채점`이 같은 작업 공간을 공유합니다. 화면의 Enter·Tab·Ctrl 키 또는 외부 키보드를 사용할 수 있습니다. 미완료 채점 후에는 터미널로 돌아가 그대로 수정합니다. 메뉴에서 터미널을 추가·전환하거나 전체 기록을 복사할 수 있고 터미널을 길게 눌러도 기록을 복사합니다. 스크롤 중 새 출력이 와도 보고 있는 과거 기록을 유지합니다.

단원별 완료 여부와 학습 소단계를 자동 저장합니다. 앱을 나가면 실습 VM을 종료하며 실습 파일·셸 세션은 보존하지 않습니다. 배운 범위 올랜덤은 메뉴의 `올랜덤 종료·복귀`로 취소합니다. 채점은 기존 실제 Linux 과정의 파일·권한·프로세스 등 실제 상태를 이용합니다. 자작 셸 명령 해석기로 바꾸지 않았습니다.

## 검증 상태

현재 자료는 Python95학습·복습/285문제, Linux90·Docker25·ROS 2 23단원과27복습, Conda·pip20학습·복습/60문제, Jupyter6학습·복습/18문제입니다. 원본 데스크톱의 문제·채점기를 빌드 때 가져오므로 별도의 정답 모사를 만들지 않습니다. 이 숫자는 자료 범위이지 모든 Android 문제를 이번에 다시 실행했다는 뜻은 아닙니다.

4.7.4의 변경분 검사 결과와 배포 파일 해시는 `../releases/android-build.json`에 기록합니다. 기존 검사 이력은 아래와 `UI_VERIFICATION.md`에 분리해서 보존합니다.

- Android15/API35 x86_64에서 91개 Python 학습·복습 항목/273문제와 오답·동등풀이98개를 실제 라이브러리로 검사했습니다. 최신 정규 계측은21개 중18실행 통과/3개 실제 VM 선택검사 제외(34.288초)입니다. 별도 실제 nano 화면 종단검사와 초반Linux20단원60개 문제의 실제 guest 채점도 확인했습니다. 60문제는 자동입력 수정 전후 두 실행에서 확인한 합계이며 전체95단원 통과를 뜻하지 않습니다. APK별 식별값·검증 시점은 `UI_VERIFICATION.md`에 있습니다.
- 2026-09-16 Android UI 개편: 기본 세로 화면, 320×568dp 작은 화면, 글자130%, 가로 화면의 UI 테스트를 수행했습니다. 키보드 위 버튼 배치, 탭 전환 시 입력 보존, 실제 실행→출력→채점 이동, 소단계 저장을 검사했습니다. 기본 세로 크기에서는 짧은 평가7개가 동시에 보이며, 긴 평가·큰 글자는 스크롤로 읽습니다. 가로+키보드에서는 탭과 실행 버튼을 한 줄로 합칩니다. 화면 캡처는 `ui-previews/`에 있습니다.
- 수정한 기능과 새 단원만 우선 검사합니다. 이미 확인한 전체 과정은 변경 영향이 없다면 반복하지 않습니다.
- ARM64 실제 휴대폰 검증은 아직 없습니다. FreeType의16KB 정렬 문제를 공식 소스 재빌드로 수정했고 ARM64 라이브러리291개(과학패키지271+부트스트랩12+JNI8)의 정렬 검사는 통과했습니다. 이것만으로 실제16KB 기기 실행까지 검증했다고 표시하지 않습니다. x86_64 일부 의존 라이브러리는4KB 전용이므로 모든 Android 기기 지원을 완료한 상태가 아닙니다.
- UI 유휴 PSS 약40MiB는 위 에뮬레이터에서만 측정한 값이며 Python 실행 중 메모리나 실제 휴대폰의 배터리 사용량을 뜻하지 않습니다.

## 개발 빌드

JDK17, Android SDK35, Gradle8.11.1, CPython3.13이 필요합니다. 일반 사용자의 실행 준비물이 아니라 개발자의 빌드 도구입니다. `SHELLGROUND_BUILD_PYTHON`에 빌드용 Python 경로를 지정합니다.

16KB 호환 FreeType 휠은 `desktop/build_android_freetype.py`로 생성합니다. 공식 FreeType2.14.3 소스(스크립트에 SHA256 고정)를 `.android-tools/freetype-2.14.3`에 준비하고 NDK27.2.12479018로 두 ABI를 빌드합니다. 생성 위치는 `desktop/.android-tools/wheels`이며 Gradle이 이 디렉터리에서 정확한 버전2.14.3을 선택합니다. 이 앱은 FreeType Team의 작업을 일부 사용합니다. 저작권과 빌드 차이는 `app/src/main/assets/third-party-notices.txt` 및 동봉 FTL.TXT에 명시합니다.

```sh
gradle --no-daemon :app:assembleDebug :app:assembleDebugAndroidTest
adb -s <전용-테스트-기기> install -r app/build/outputs/apk/debug/app-debug.apk
adb -s <전용-테스트-기기> install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s <전용-테스트-기기> shell am instrument -w -e class org.shellground.learn.PortDeltaTest -e real_port true org.shellground.learn.test/androidx.test.runner.AndroidJUnitRunner
```

개발 키 파일은 현재 `../desktop/.android-tools/debug.keystore`를 사용합니다. 개인 서명 키는 저장소에 포함하지 않습니다. 정식 배포 시 독립 릴리스 키·서명·업데이트 정책을 별도로 설정해야 합니다. Python 환경과 강의 데이터는 `../desktop/python_teaching`을 빌드 때 공유하며, 앱과 desktop의 문제/채점 복사본을 따로 손으로 수정하지 않습니다.

실제 Linux 포함판은 검증된 native 후보와 guest 팩을 준비한 개발 환경에서 다음 옵션으로 빌드합니다. 자세한 준비·검증 경계는 [실행기 문서](runtime/README.md)를 따릅니다.

```sh
gradle --offline --no-daemon --max-workers=1 -PlinuxRuntime=true -PbundleLinuxPack=true :app:assembleDebug :app:assembleDebugAndroidTest
```

검증용 VM과 큰 빌드는 직렬로 실행하고 온도를 확인합니다. Linux 팩은 원본·매니페스트·스테이징 코드·생성물이 그대로면 재분할하지 않습니다. 변경된 팩을 실제 스테이징할 때의 SHA256 검증은 유지합니다.

## Conda·pip와 Jupyter

Conda 과정의 답칸과 터미널은 같은 실습 상태를 사용합니다. 메뉴의 선택 설치 실습은 배포판·경로·공식 체크섬·라이선스를 먼저 보여 주며, 사용자 동의 없이 배치 설치하지 않습니다. 호스트 Android에 Conda를 설치하는 것이 아니라 앱 안의 ARM64 Linux에 설치합니다.

Jupyter는 `문제·설명 / Bash / 채점 / 노트북` 탭을 공유합니다. 노트북에서 실제 커널과 Python 경로를 확인하고 코드·Markdown 셀을 편집·실행·재정렬하며 `.ipynb`로 저장할 수 있습니다. Bash에서 환경을 활성화하는 것과 노트북 커널 선택은 별개입니다. 실패한 채점 뒤에도 셀과 같은 커널에서 계속 수정할 수 있습니다. 저장한 노트북은 해당 임시 실습 환경 안에 있으므로 앱 종료 후 보관용 파일로 간주하지 마세요.
