# 학습 순서와 설계 이유

## 4.6 실제 Linux 밀도 재설계 — 현재 과정

실제 Linux 60 + Docker 15 + ROS 2 20 = 95단원, 분야별 5단원마다 19종합 복습입니다. 모의 과정/엔진은 변경하지 않습니다. 아래의 이전 버전 절은 당시 설계 이력입니다.

| Linux 번호 | 개념 순서 | 묶은 이유 |
| --- | --- | --- |
| 01–05 | pwd/cd와 오류 읽기 → pwd -L/-P → ls/-a → -l/-al → cat | 경로·목록·내용을 구분하고 파일 변경 없이 관찰 |
| 06–10 | 출력 저장 → 숨김 이름 목록 저장 → 상세 목록·현재 경로 → -h 크기 단위 → -S/-1 정렬 | ls를 뒤로 흩어 놓지 않고 출력 목적을 하나씩 추가 |
| 11–15 | -a/-A 비교·조합 → -R 전체 구조 → mkdir → touch → nano | 목록 조회를 마친 뒤 작업 폴더·파일 작성으로 연결 |
| 16–20 | cp → mv → rm → mkdir -p/공백 경로 → 복사·변경·삭제 조합 | 원본/대상을 구분한 뒤 중간 폴더·백업·복구 |
| 21–25 | 위치·목록 인계 → 기본 grep → head → tail → wc -l/입력 리다이렉션 | 검색·줄 수·파이프를 한 화면에서 처음 소개하지 않음 |
| 26–30 | 파이프 → grep -i 조합 → find → 실행 권한 → curl | 내용 처리와 파일 찾기를 구분하고 다운로드로 연결 |
| 31–35 | wget → tar 내부 목록 → tar/zip 해제 → 스크립트 실행 → deb 정보 | 받기·조회·해제·실행의 서로 다른 역할을 구분 |
| 36–40 | deb 추출 → 환경변수 → 스크립트 작성 → 작업 제어 → APT | 복합 단원 안에서도 2–4개의 설명·실습 소단계 |
| 41–45 | 이름/UID → 기본·보조 그룹 조회 → 계정 레코드 → 조사 조합 → 기호 권한 | 생성 전에 조회 결과를 읽는 능력부터 확보 |
| 46–50 | 숫자 권한 → 폴더 권한 → chown → chgrp → 소유권 조합 | 권한과 소유권을 섞지 않고 각각 연습 |
| 51–55 | 그룹 생성 → useradd -u → -d/-m → -s → -g | 그룹을 먼저 만들고 사용자 설정 한 개념씩 추가 |
| 56–60 | useradd -G → 생성 옵션 조합 → usermod -a/-G → -g → 그룹 복구 조합 | 새 계정 생성과 기존 계정 변경을 분리 |

`useradd -u -d -m -s -g -G` 전체 예시는 57에서 복습 조합으로 만납니다. 52에서 모두 처음 암기하도록 요구하지 않습니다. -d/-m처럼 같은 목적의 서로 다른 동작은 한 단원 안의 소단계에서 비교합니다. 모든 기존 단원 키와 내용을 유지하고 새 25단원에 새 키를 부여합니다.

초반 복습/활용에는 아직 배우지 않은 cp·mkdir·리다이렉션을 요구하지 않습니다. 화면 상세 목록은 실제 ls 출력의 필드를 확인하여 채점하고, 보고서 단원부터 파일 결과를 검사합니다. 새 종합 복습도 새 5단원 묶음에 맞췄습니다. 이전 구성 복습 기록은 보존하지만 다른 내용의 새 복습을 자동 통과로 만들지 않습니다.

소단계는 위치와 확인 이력을 저장합니다. F6으로 넘어간 확인 이력은 단원 숙달과 다르며 활용 문제 통과가 필요합니다. 재실행 때 임시 실습 상태를 재현하거나 명령을 자동 실행하지 않습니다. 앞 단계 작업이 필요한 경우 ‘재개 준비 명령’을 통해 해당 실습의 경로에 맞는 준비 설명을 확인합니다.

검증: 25신규×3변형을 실제 Linux에서 실행했고, 12개 새 복습·2개 초반 조정 문제 및 실제 Linux 소단계 풀이를 검사합니다. 기존 범위의 모든 옵션·전체 강의·Windows 검증이 완료됐다는 뜻은 아닙니다. 상세 결과는 [VERIFICATION.md](VERIFICATION.md).

## 4.3 Docker 심화 (실제 모드)

실제 70단원·14복습, 모의 45단원·9복습입니다. 리눅스 35 / Docker 15 / ROS 2 20으로 표시하며 기존 완료 키를 바꾸지 않습니다. 아래 단원은 Docker 10 뒤에 이어집니다. 선행 완료 잠금은 없습니다.

| Docker | 배우기·예시 | 활용 1 | 활용 2 |
| --- | --- | --- | --- |
| 11 | 입력 ro·출력 rw 마운트, 숫자 UID/GID | 뒤바뀐 읽기/쓰기 마운트 교체 | 이전 chown 지식으로 쓰기 권한 복구, 공백 경로 유지 |
| 12 | 이름 있는 볼륨·일회성 작성 컨테이너 | 빈 볼륨에 잘못 연결된 컨테이너 복구 | 읽기 전용 원본 → 공백 폴더 백업 → 새 볼륨 복원 |
| 13 | 사용자 정의 bridge와 DNS 별칭 | 컨테이너 ID 유지하며 기본 bridge 연결 복구 | 이전 네트워크에서 새 네트워크로 이관·정리 |
| 14 | FROM/COPY/RUN/WORKDIR/USER/CMD | 잘못된 COPY와 사용자 설정 수정 | 기존 이미지 보존하며 새 버전 빌드·실행 보고서 |
| 15 | 실패 로그·종료 코드 보관 후 재시작 | 누락된 입력을 원본에서 복구 | root 전용 설정 파일의 최소 권한 복구 |
| 11–15 복습 | 실패 서비스를 수정·교체하고 원본 볼륨 보존, 네트워크·별칭·ro/rw 연결 | 다른 컨테이너에서 실제 통신 | 결과 데이터와 원본 보존 확인 |

같은 결과의 `-v`/`--mount` 대안을 인정합니다. 잘못된 마운트, 원본 삭제, 컨테이너 재생성 후 ID 보존 주장, 실제 이미지 없이 보고서만 만든 풀이는 미완료입니다. 실패 후 같은 실습을 계속 수정하고 재채점합니다. 아래 4.2·4.0 절의 단원 개수는 당시 이력입니다.

## 4.2 계정·권한 과정 (모의/실제 모드 공통)

현재 모의 모드는 45단원·9복습, 실제 모드는 ROS 20단원을 포함한 65단원·13복습입니다. 2026-09-16부터 표시 번호는 리눅스 01–35 / Docker 01–10 / ROS 2 01–20으로 나눴습니다. 기존 저장 키는 유지하므로 진도는 보존됩니다. 아래 4.0 기록은 이전 구성의 이력이며 그 번호는 당시 전역 번호입니다. 4.2.2부터 사용자 요청으로 선행 완료 잠금을 제거했습니다. 모든 단원과 종합 복습에 직접 진입할 수 있으며, 추천 순서와 완료 판정은 별도로 유지합니다.

| 리눅스 단계 (두 모드 공통) | 새 내용 | 활용 문제의 차이 |
| --- | --- | --- |
| 31 | whoami, id의 UID/GID/그룹 이름, getent 계정 조회 | 현재 사용자 조사 → 다른 계정 조사 → 계정 레코드와 공백 이름 백업 인계 |
| 32 | 숫자/기호 chmod, 파일 실행과 폴더 탐색 권한 | 최소 권한 설정 → 탐색 불가 폴더 복구 → 비공개 원본을 유지한 공유 복사본 |
| 33 | sudo, chown, chgrp | 자신의 작업 권한 복구 → 다른 사용자에게 인계 → 소유자를 유지한 그룹만 변경 |
| 34 | useradd의 UID/기본·보조 그룹/홈/셸/홈 생성 | 계정과 실제 홈 생성 → 다른 로그인 셸 구성 → 앞서 배운 복사·소유권으로 인계 파일 준비 |
| 35 | groupadd, usermod의 -g/-G/-a 차이 | 기존 보조 그룹을 유지한 추가 → 기본 그룹 변경 → 누락된 그룹 복구 |
| 종합 복습 | 다섯 단원과 앞서 배운 파일 조작 | 계정·홈 생성 → 새 그룹 추가 → 기존 그룹 보존 → 공백 이름 원본 인계 → 파일 권한·소유권 → UID/그룹 보고서 |

문제에는 목표 상태를 제시하고 풀이 문자열로 채점하지 않습니다. `-a`를 빼서 기존 그룹을 잃거나 홈 경로만 계정에 기록하고 실제 폴더를 만들지 않으면 미완료입니다. 같은 상태에서 복구하고 다시 채점할 수 있습니다. 원본과 무관한 파일도 보존해야 합니다. 새 종합 복습의 저장 키는 `admin-checkpoint-accounts`로 ROS 복습 키와 충돌하지 않습니다.

`usermod -G`의 교체와 `-a`의 추가, `-g`와 홈 안의 그룹 소유 변경은 [Ubuntu 22.04 usermod 설명](https://manpages.ubuntu.com/manpages/jammy/man8/usermod.8.html)을 기준으로 실제 도구와 대조했습니다. 암호 설정·로그인 전환·sudoers·setuid, 패키지 심화와 나머지 강의 범위는 다음 확장 대상이며 이 다섯 단원으로 전체 완료를 주장하지 않습니다.

## 5개 단원마다 종합 복습

기존 단원 번호는 그대로 두고 05·10·15·20·25 뒤에 별도 종합 테스트를 배치했습니다. 해당 구간의 다섯 기능을 한 작업 공간에서 함께 사용합니다. 목표만 보고 해결하며 F1 힌트, F3 해당 다섯 단원 설명을 필요할 때 열 수 있습니다.

| 01–05 | 이동·숨김 목록·공백 파일 읽기 → 작업 폴더와 빈 파일 준비 |
| 06–10 | 원본 백업 → nano 수정·저장 → 이름 변경·삭제 → 위치 보고서 |

한 단원당 기존 예시·활용 1·활용 2는 유지합니다. 각 종합 테스트를 통과하면 다음 미완료 단원이 열립니다. 종합 복습 완료 기록은 단원 진도와 구분해 자동 저장하며, 중간에 종료한 테스트는 미완료로 남습니다. 완료한 복습을 다시 선택하면 새로운 경로 조건으로 재응시할 수 있습니다. 기존에 완료한 단원은 다시 잠그지 않습니다. 26번 패키지 단원은 그대로 유지합니다.

## 기본 단원

경로는 작업 상황에 맞게 섞습니다. 시작 위치가 작업 폴더 자체인 경우, 부모·인접 폴더인 경우, 멀리 떨어진 경우를 생성합니다. 01에서 절대경로와 상대경로, 현재 폴더(.)·부모 폴더(..)와 이동 시 기준 변경을 소개합니다. 가까운 대상은 파일명·하위 경로·../로 접근하고, 먼 폴더에서 여러 작업을 할 때는 한 번 이동한 뒤 작업합니다. 먼 대상의 일회성 접근과 절대경로 목록을 요구하는 find는 절대경로 예시를 유지합니다.

문제에 표시된 상대경로는 시작 위치 기준이며, 예시 풀이의 상대경로는 각 명령을 실행하는 시점의 현재 위치 기준입니다. 채점용 경로는 절대경로로 별도 유지합니다. 경로 입력 방식은 강제하지 않고 목표 파일·내용·현재 위치가 맞는지 검사하므로 동등한 절대/상대경로 풀이를 인정합니다. 기존 26개 단원 및 모든 옵션 설명은 유지합니다.

먼저 파일을 직접 다루고, 그다음 옵션과 조합을 배웁니다. 특정 명령의 모든 옵션을 한 번에 외우는 순서는 사용하지 않습니다. 각 단원은 짧은 설명과 F4 자유 연습 → 예시 실습 → 활용 1(핵심 기능) → 활용 2(조합·복구) → 완료 기록으로 진행합니다. 자세한 옵션 설명은 F3으로 따로 확인합니다.

| 12 | cp·mv·rm 조합 | 개별 작업을 배운 뒤 묶어서 수행 |
| 13 | ls -a 보고서 | 목록 조회와 출력 저장 결합 |
| 14 | ls -l·-al 상세 목록 | 새 옵션 -l 하나를 기존 -a와 결합 |

활용 2는 같은 경로 seed를 써도 활용 1과 과제가 다릅니다. 예: 폴더 생성은 위치 이동 후 두 작업 폴더 만들기, 복사는 두 파일 백업, 편집은 기존 항목을 보존한 설정 복구, 로그는 두 파일을 합쳐 필터·집계, 다운로드는 손상 파일 보존 후 재다운로드입니다. 올랜덤에는 두 유형 모두 포함합니다.

기존 15개 단원은 모두 유지하며 기본 단원을 추가해 26개로 나눴습니다. 기존 완료 기록은 단원 이름이 아닌 고정 키로 읽기 때문에 순서가 바뀌어도 사라지지 않습니다. 새 단원은 미완료로 표시합니다.

처음 배우는 pwd/ls/cat 화면 실습은 파일 저장을 요구하지 않습니다. 실제 터미널 출력으로 확인하며 이 출력은 현재 문제의 메모리에만 보관하고 진도 파일에는 저장하지 않습니다. nano는 모사 화면이 아닌 컨테이너의 실제 편집기입니다. 파일 수정은 저장된 실제 내용으로 검사합니다.
