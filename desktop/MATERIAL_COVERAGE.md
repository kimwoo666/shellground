# 제공 강의자료와 실습 범위 대조

검토일: 2026-09-16. 현재 개발 소스: **4.3.0-dev. 기존 40단원·8복습과 계정·권한 5단원·1복습을 보존하고 실제 Docker 심화 5단원·1복습을 추가했다. 모의 45단원·9복습, 실제 70단원·14복습이며 전체 자료 범위 확장과 Windows 런타임 검증은 미완료**.

최신 사용자 요구가 이전의 시뮬레이터 전용 방침을 대체한다. **시뮬레이션 모드는 보존하고 실제 Linux 모드를 별도로 추가**한다. 사용자는 별도 환경 설정 없이 앱을 실행·종료해야 하며, 실제 모드의 전용 실행 환경은 앱이 관리한다. 사용자가 제공한 **Linux·Docker·ROS 2 자료의 명령어, 하위 명령, 옵션 및 조합은 최소 학습 범위**다. 실무 보완 내용은 추가하되 기존 내용을 삭제하거나 쉬운 하위 집합만 구현해서 전체 완료로 표시하지 않는다. 실제 주행 시뮬레이션은 대상이 아니다. 상세 완료 기준은 [개발 목표](DEVELOPMENT_GOALS.md)를 따른다.

기존 26단원을 내부 파일 시스템에 연결했고 27–30에 환경변수·스크립트 작성·작업/시그널·패키지 관리, 31–40에 Docker 이미지·실행·상태·파일 작업·정리·갱신·태그·commit·save/load·자원 설정 과제를 추가했다. 아래 원래 대조표의 '현재 상태' 열은 **3.6 당시 상태**를 보존한 것으로, 최신 구현 목록은 README.md와 LEARNING_PATH.md가 기준이다. 설명만 존재하는 항목을 독립 실습 또는 숙달 완료로 세지 않는다.

추가 구현: 사용자·그룹 조사, 숫자/기호 권한, 소유권, `useradd -u/-g/-G/-s/-d/-m`, `groupadd -g`, `usermod -a/-G/-g`를 모의·실제 모드의 상태 채점과 연결했다. 실제 게스트의 다섯 단원 모든 변형과 종합 문제를 검사했다.

추가 실제 Docker 범위: 강의 2a PDF 41–42쪽 및 부록 29–33쪽의 실행 옵션·공유 경로·UID/GID·Dockerfile 내용을 출발점으로, Docker 11–15에 bind ro/rw·숫자 사용자, 이름 있는 볼륨과 백업 복원, 사용자 정의 bridge와 별칭·이관, Dockerfile 빌드·버전 보존, logs/종료 코드/파일 권한 복구를 연결했다. 자료를 옮겨 적지 않고 독자적인 실패 상태와 목표 문제를 작성했다. 공식 [bind mount](https://docs.docker.com/engine/storage/bind-mounts/), [volumes](https://docs.docker.com/engine/storage/volumes/), [bridge](https://docs.docker.com/engine/network/drivers/bridge/), [Dockerfile](https://docs.docker.com/reference/dockerfile/) 문서를 참고했다. 실제 게스트에서 15개 변형과 종합 복습 및 오답을 확인했다. 이 범위가 PDF 해당 쪽의 모든 옵션을 다뤘다는 뜻은 아니다.

남은 주요 범위: passwd/su와 sudoers/setuid, 계정 정책 심화, 시스템 시간/네트워크 관리, 패키지 의존성·snap, Docker attach/포트 실제 통신/device/privileged/GPU·cpuset/I/O와 stats 해석, 고급 셸 문법·정규식·심화 옵션의 독립 과제. GPU 옵션 학습은 의미·요구 조건·지원되지 않는 환경의 실제 오류를 다루며 실제 GPU가 필요한 주행 실행 기능은 아니다. 기존 시뮬레이터를 확장하는 것보다 실제 OS에서 문제와 채점을 완성하는 것이 우선이다.

## 숙달 판정 원칙

1. 짧은 새 내용 → 설명을 보며 직접 조작 → 예시 → 핵심 활용 → 다른 방식의 이전 기능 조합 → 5단원 종합 → 완료 범위 랜덤.
2. 이름만 바꾼 반복 대신 조사·생성·복구·비교·선택 작업을 섞는다. 인접 파일에는 상대경로, 먼 대상에는 절대경로를 자연스럽게 사용한다.
3. 실습은 실제 명령 출력·파일·권한·프로세스·컨테이너 상태로 판정한다. “명령을 설명했다”는 이유만으로 실습 통과를 주지 않는다.
4. 개념 문제는 정답뿐 아니라 근거 선택·잘못된 설명 교정도 평가한다. 미완료 항목은 계속 수정해 재채점하며, 정답/조작법은 시험 화면에 자동 노출하지 않는다.
5. 완료 기록은 항목별로 저장한다. 하드웨어가 없어 미실행한 과제는 미완료/환경 필요로 남긴다. 기존 완료 기록과 기억노트를 보존한다.

## 원문을 그대로 정답으로 삼으면 안 되는 부분

- `id`는 이 실습의 Ubuntu/bash에서 외부 프로그램이다. `pwd`/`cd`와 명령 종류를 구분한다.
- `ls -l` 기본 시각은 생성 시각이 아니라 수정 시각이다. 텍스트 파일도 UTF-8 등으로 ASCII 범위 밖 문자를 담을 수 있다.
- SIGKILL뿐 아니라 SIGSTOP도 잡거나 차단하거나 무시할 수 없다.
- bash `-C`는 noclobber 옵션이다. 스크립트를 실행하기 위해 일반적으로 필수인 옵션이 아니다.
- `docker run --rm`은 종료된 컨테이너를 정리하며 기반 이미지를 삭제하는 옵션이 아니다. commit은 실행 중 RAM 상태를 저장하는 기능이 아니다.
- 숫자 UID로 컨테이너 실행 시 반드시 해당 이름의 passwd 항목이 필요한 것은 아니다. sudo 권한은 정책 설정에 따른다.
- `--privileged`와 호스트 장치·디렉터리 공유 예제는 그대로 실행하지 않는다. cgroup 경로와 I/O 제한 효과는 환경에 따라 검증한다.
- 강의의 연도별 가격·TOPS·기업 사례는 당시 자료로 표시한다. 출처 불명 AI 응답의 수치, 비공식 L2+ 표현, 운전자 주의 의무를 약화하는 설명을 검증 없이 정답으로 넣지 않는다.

검증 참고: [Bash 매뉴얼](https://www.gnu.org/software/bash/manual/bash.html), [Linux signal 매뉴얼](https://man7.org/linux/man-pages/man7/signal.7.html), [Docker run 문서](https://docs.docker.com/reference/cli/docker/container/run/).

## 환경 및 자료의 한계 — 전체 구현 전에 해결할 사항

4.0은 실제 Linux 컨테이너나 가상머신을 생성하지 않는다. 사용자 경로는 메모리 내부에서만 해석하고 Docker 소켓·개인 폴더·네트워크에 연결하지 않는다. 진도와 명시적으로 저장하는 기억노트만 호스트 사용자 데이터 폴더에 저장한다.

시뮬레이션 전용으로 한정했던 이전 방침은 최신 요구로 변경되었다. 기존 모의 엔진은 유지하며 실제 모드는 앱 전용 QEMU 게스트를 사용한다. Linux 개발 팩의 네트워크 없는 시작·채점·정상 종료와 앱 비정상 종료 뒤 정리를 검증했지만, Windows 런타임/실기기 검증은 미완료다. 미구현 명령/옵션을 성공으로 위장하거나 실제 모드를 시뮬레이터로 대체하지 않는다. 원문의 위험한 옵션을 사용자 PC에서 실행하지 않으며 실제 모드에서도 앱 전용 게스트 범위로 제한한다.

1주차 소개 자료에 나열된 ROS2/ROSCPP·제어/계획/추정 알고리즘의 후속 교재와 E2E 부록, 링크 영상의 전체 내용은 이번 네 PDF에 모두 담겨 있지 않다. 이 주제들의 구현 숙달까지 요구한다면 해당 자료가 추가로 필요하다. 이번 대조는 제공된 본문·표·그림 범위이며 연결된 외부 영상을 전부 시청했다는 뜻이 아니다.
