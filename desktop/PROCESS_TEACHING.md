# 프로세스 조사·작업 제어 학습

Linux 76–80번과 복습을 추가했다. 기존 완료 키와 가상 Linux 엔진은 변경하지 않는다. 아직 새 배포 실행파일에 포함하기 전이며, 실제 전용 Linux의 ps·pstree·Bash 작업 제어·시그널로 실습한다.

| 단원 | 새 개념 | 활용의 차이 |
| --- | --- | --- |
| 76 | ps -U/-p, PID·TTY·TIME·CMD | 낡은 보고서를 보존하며 갱신 / 한 서비스만 별도 조사 |
| 77 | ps -Lf, PPID·LWP·NLWP, pstree -p -u | 다른 서비스의 스레드 비교 / 실제 스레드 수 집계 |
| 78 | jobs -l, fg, Ctrl+Z | 잘못 중지된 다른 작업 복구 / 재귀 목록 보고서 보존 |
| 79 | bg, &, $!, wait | 다른 중지 작업도 복구 / 백그라운드 보고서 완성 후 확인 |
| 80 | TERM과 KILL, 실제 종료 상태 | 중지 상태에서 정상 종료 / 보존 서비스는 중지 상태 유지 |

각 단원은 설명을 보며 실행하는 2–3개 소단계를 제공한다. 복습에서는 종료 전에 스레드와 트리를 보관하고 정상 종료가 가능한 서비스, TERM을 무시하는 서비스, 보존할 서비스를 구분한다. TIME은 경과 시간이 아니라 누적 CPU 시간이며, S(정상 대기 가능)와 T(중지)를 구별한다. 스레드 수로 고정 성능 향상을 주장하지 않는다.

## 실제 동작과 자원 관리

준비된 세 작업은 대부분 이벤트를 기다린다. main에는 실제 스레드 세 개가 있다. 무한 계산이나 호스트 전체 디렉터리 탐색으로 부하를 만들지 않는다. 서비스 감독은 실제 종료 상태 0/시그널 -9를 관측하며 상태 파일은 변경 시에만 기록한다.

작업 제어 과정은 현재 Bash의 실제 작업 그룹을 사용한다. .bashrc 실행 도중에는 작업 제어 초기화가 끝나지 않아 자식들이 셸과 같은 그룹이 되는 문제를 발견했다. 최초 프롬프트에서 한 번만 준비하도록 바꾸었고 이후 프롬프트에는 추가 Python·sudo 실행이 없다. PID·시작 시각·UID·소유 프로그램을 함께 확인해 무관한 프로세스를 종료하지 않는다.

종료 실습에서 실수했으면 준비된 `./restart-services.sh`로 서비스 세 개만 다시 시작할 수 있다. 파일과 터미널은 유지하며 PID 파일이 갱신된다. 일반 Linux 명령이 아니라 이 실습의 복구 도구임을 설명한다. 문제 전환·VM 종료 시 소유 작업·감독·부트스트랩을 정리한다.

## 채점과 증분 검증

보고서는 실제 프로세스 식별자·스레드 집합·부모 트리·상태·CPU 시간과 비교한다. 표의 TT/TNAME·COMMAND/COMM 별칭과 ASCII/UTF-8 트리, 숫자 정렬·스레드 숨기기 같은 유효한 표현을 허용한다. 평면 이름 나열이나 불가능한 CPU 시간은 거부한다. 최대 7항목으로 상태 및 원본·PID 파일 보존을 평가한다.

- 새 교육 계약/등록/기존 키/업로드 검사 9개와 CPU 시간·열 별칭 검사 1개 통과. `bash -n` 통과. 기존 전 과정 검사를 반복하지 않았다.
- `process-new.json`: 목록·스레드 6문제 PASS 후 최초 작업 제어 준비 오류로 실패. 22.45초, VM/임시 디스크 정리 true. 진단 보고서는 `process-stop-diagnose.json`에 보존했다.
- `process-control.json`: 준비 수정 후 중지·재개·시그널·복습 10문제 및 오답/복구/수명 4종 PASS. 32.30초, 정리 true. 동일 PID 재개와 전경/백그라운드를 실제 PTY로 확인했다.
- `process-grading-delta.json`: 감사 변경 영향 목록/스레드 2문제와 보고서 오답/동등 3종 PASS. 마지막 PID 위조 검사는 root 소유 파일을 일반 사용자로 덮어쓰려다 변경 자체가 거부되어 검사 준비가 실패했다. 제품이 실제 변조를 통과시킨 증거가 아니다. 17.30초, 정리 true.
- `process-pid-delta.json`: 위조 준비를 전용 게스트의 sudo로 수행하고 실제 파일이 바뀌었는지 먼저 확인하도록 수정했다. 영향 스레드 1문제와 스레드/트리·PID 보존·수명 3종 PASS, 16.88초, 정리 true. 다른 15문제는 반복하지 않았다.

각 보고서는 `.jupyter-build`에 소스 해시와 함께 별도로 보존했다. 초기 6문제+수정 10문제+변경 영향 검사들의 증거이지, 최종 버전의 모든 문제를 다시 실행한 단일 보고서라고 주장하지 않는다. CPUQuota60%·nice15, 검사 동안만 절전 방지. 검사 사이 CPU39–44°C 관측.
