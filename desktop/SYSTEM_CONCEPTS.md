# Linux·Docker 개념 배우기와 퀴즈

Linux 검토용 개발 소스에 연결했다. 새 실행파일 배포와 다른 OS 검증은 아직 전이다. 실제 Linux 모드의 상단 **Linux·Docker 개념 배우기·퀴즈**에서 연다. 개념 화면 자체는 VM이나 컨테이너를 실행하지 않는다.

## 사용 방법

1. Linux 또는 Docker와 원하는 문제를 고른다. 선수 개념을 짧은 카드로 먼저 볼 수 있다.
2. 퀴즈 탭에서 가정 자료를 읽고 답을 고른다. 정답·보기별 해설은 제출 전에 공개하지 않는다.
3. 답 확인 후 채점 결과 탭으로 자동 이동한다. 틀렸으면 문제로 돌아가 바로 다시 고를 수 있다. 재시작할 필요가 없다.
4. 관련 실습에서는 연결된 단원 설명으로 이동한다. 현재 실습이 미완료라면 임시 상태를 버릴지 묻고, 취소하면 그대로 둔다. 이동만으로 명령 실행·채점·실습 완료를 하지 않는다.

문제 선택과 다음 이동에는 완료 잠금이 없다. 정답 여부·시도 횟수와 분야별 문제/개념 카드 위치는 `system-concepts-v1.json`에 자동 저장한다. 이전 답안 선택 자체는 재개하지 않는다. 기존 Linux·시뮬레이션·Python 완료 기록과는 별도다. 손상되거나 미래 형식인 기존 파일은 경고하고 덮어쓰지 않는다.

## 등록 범위

고유 개념33개, Linux33문항/Docker11문항으로 총44문항이다. 기존38문항/28카드의 ID·내용·순서와 Python·데이터 카드36개/퀴즈61개는 보존했다. I/O의 입력/EOF·more·tree·실행 권한·해석기 선택 6문항에 이어, 시스템 조사 5개념/6문항을 Linux 목록 끝에 추가했다.

- Linux: 터미널/셸/커널/배포판/POSIX, 내장·외부 명령, UTF-8 바이트, UID/정책/setuid 조건, PATH/source/인자/분기/noclobber, 프로세스·스레드·CPU 시간·대기/중지·작업 번호·시그널, I/O·실행 기본, 커널/배포판/호스트 이름과 DNS의 구분, 인터페이스/주소/관리 UP, epoch/UTC, 시스템 시계/RTC/NTP, snap 클라이언트/데몬/패키지.
- Docker: VM/공유 커널/client/daemon/OCI, attach/exec 수명, cgroup·CPU 위치/시간 상한, I/O 상대 가중치, 장치/GPU 최소 권한, X11 주소/인증과 그래픽·계산의 구분.

37문항은 현재 관련 실습 설명에 연결하고, 7문항은 직접 연결할 평가가 없어 미연결로 표시한다. Docker 후속 과정에서 기존5문항의 관련 링크만 갱신했다: attach/exec→실제 대화형16–20, CPU→stats·cpuset/시간 상한, I/O→실제 가중치 적용. 문항·보기·정답·해설·ID는 그대로다. 실제 성능 비교·장치·GPU·X11 성공을 대신 부여하지 않으며, I/O 가중치 설정 확인도 장치 처리량 검증과 구분한다.

시스템 조사 문항은 `system_identity`·`system_links`·`system_addresses`·`system_time`·`system_clock`의 설명에 연결한다. 이름·주소·UP 조회는 DNS 등록이나 통신 성공을 검증하지 않는다. RTC 미지원 오류를 정확히 보고한 조사 완료는 RTC 읽기 성공 또는 NTP 동기화 완료가 아니다. Snap은 실제 설치·실행 평가가 없어 미연결이며, 명령이나 `.snap` 파일의 존재만으로 설치 성공을 표시하지 않는다. 원문의 공식 근거 URL과 가정 자료를 유지한다.

퀴즈 에이전트의 다섯 `*_concept_draft.json` 원본과 고정 ID는 보존했다. `system_concepts.py`가 검토된 표시 예시·선수 개념·관련 범위를 더해 실제 UI 카탈로그로 읽는다. 원문 ID·보기·정답·해설을 유지하고, 카드 예시는 문제의 같은 숫자와 정답을 그대로 옮기지 않도록 바꿨다. 초안의 미연결 표시는 작성 당시 기록이며 현재 카탈로그 연결 상태는 이 문서에 따른다. 사용자 강의 PDF는 재배포하지 않는다.

## 증분 검증

- Docker16–25 연결 증가분: 기존5문항의 관련 실습 경로 갱신,정적/직접 영향4검사 PASS0.031초. 설명 이동 UI1검사 PASS0.045초:5문항의9경로가 선택한 단원 키를 전달하고 자동 채점/완료를 쓰지 않는다. 기존 퀴즈를 재채점하지 않았다.

- 시스템 조사 증가분: 신규 정적4검사 PASS, 0.008초. 기존38문항 데이터·순서를 보존했다. 이어 새6문항 전용 UI1검사 **PASS0.35초** (`.jupyter-build/system-concept-ui.json`, scope `system-concept-ui-new-20260918`, exit0). 표시·정답 사전 비공개·오답 재시도·진도 재개·근거/미지원 경계를 확인했다. 소스 해시 전후 일치, VM·기존38문항 재실행 없음.

- I/O 증가분: 직접 영향 카탈로그5검사 PASS0.012초. `.jupyter-build/io-concept-ui.json` 신규6문항의 표시·정답 비공개·채점 탭·재개를 확인하는1검사 PASS0.30초. 기존32문항 전수/VM은 반복하지 않았다. 빌드 자산에 네 번째 JSON도 추가했다.

- `.jupyter-build/concepts-new.json`: 새 카탈로그17+진도/UI8 = 25검사 PASS, 0.91초.
- 시각 검수 후 질문 우선·압축 가정 자료·독립 채점 탭으로 조정했다. `.jupyter-build/concepts-layout-delta.json`: 영향받는 형식3/UI4 = 7검사 PASS, 0.82초. 바뀌지 않은18검사는 반복하지 않았다.
- 반복 열기 시 닫힌 대화상자 위젯을 해제하도록 보완하고 `.jupyter-build/concepts-dialog-lifetime.json`에서 영향1검사 PASS, 0.35초. 완료 후 부모 창에 대화상자가 남지 않는 것을 확인했다.
- 모든32문항의 가정/코드/빈 인자 표시, 정답 사전 비공개, 오답 재시도, 분야별 카드 위치 재개, 손상 파일·기존 학습 진도 보존, 관련 실습 이동 취소/허용, 자동 실행 없음, 잘못된 자료 안내를 확인했다.
- `.jupyter-build/concepts-ui-delta`의 진입 메뉴, Linux 문제, Docker 다크 개념, 작은 화면 채점 탭 캡처를 직접 확인했다. 긴 내용은 각 탭 안에서 스크롤하며 문제·보기·해설을 한 공간에 겹쳐 축소하지 않는다.
- CPUQuota60%·nice15, 검사 동안만 절전 방지. VM·커널·Docker 실습은 실행하지 않았고 기존 실제 과정도 반복하지 않았다.

이는 소스와 네이티브 UI 연결의 증거다. Linux 전체 누락, 장치 실습 또는 Windows/Android 포팅 완료를 뜻하지 않는다.
