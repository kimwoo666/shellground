# 실제 Jupyter 학습 — 최종 감사 반영, Linux 재검증 중

2026-09-17 사용자는 이 기능과 남은 학습 범위 검증을 마친 후 Windows → Android → macOS 포팅을 시작하도록 승인했다. 미검증 플랫폼을 완료로 표시하지 않는다. 기존4.7.3 검토판과 진도는 보존한다.

## 실행 구조

웹 서버나 별도 창 없이 Python 학습 화면 안에서 코드 셀·Markdown 셀을 편집한다. 공식 IPython kernel과 jupyter_client를 사용한다. Jupyter 메시지·커널 상태를 자작 모사하지 않는다.

앱 전용 Linux의 별도 임시 VM에 두 Conda 환경을 준비한다. 각 환경에 실제 ipykernel을 설치·등록하며 하나에는 공식 NumPy를 설치한다. 커널 선택에 따라 실행 Python 경로·prefix·설치 패키지가 실제로 달라진다. 커널은 learner 권한으로 실행하고 호스트 개인 Python/Jupyter/Conda를 찾거나 등록하지 않는다.

관리 통신은 기존 VM 제어 채널 안에서 이루어진다. Jupyter의 ZeroMQ 포트는 게스트 loopback에만 바인딩한다. 실제 실행은 비동기 작업으로 요청하고 대기·중단·재시작·종료를 구분한다. 코드 실행 동안 UI 스레드를 막거나 busy loop를 돌리지 않는다. 실행은 메시지의 parent id와 idle/execute_reply를 함께 확인해 이전 셀의 출력이 다음 셀로 섞이지 않게 한다.

## 학습·채점 원칙

커널 이름만 바뀌었는지 보지 않고 실행 프로세스·환경 경로·실제 import·실행 결과를 검사한다. 저장된 노트북 출력만 남고 커널에 값이 없는 경우를 완료로 인정하지 않는다. 커널 재시작은 변수 상태를 지우지만 셀의 코드는 남긴다. 다시 시작한 빈 커널에서 위→아래 실행해 재현할 수 있어야 한다. 오답은 같은 노트북에서 고쳐 재채점하며 예시/소단계 확인을 숙달 완료로 환산하지 않는다.

노트북의 파일 저장과 커널 변수의 수명은 구분한다. .ipynb는 nbformat으로 읽고 쓰며 JSON 모양만 흉내 내지 않는다. 앱 재실행 진도에는 완료/마지막 학습 위치만 저장한다. 임시 코드·노트북 파일·커널 메모리는 자동으로 개인 파일로 저장하지 않는다.
