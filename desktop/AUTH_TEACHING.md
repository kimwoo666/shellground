# 계정 인증·로그인 학습

Linux 66–70번에 암호 상태 → 암호 설정·교체 → 일반 사용자 전환 → 로그인 환경 → 허용된 관리자 명령을 배치했다. 각 단원은 설명과 함께 조작하는 2–3개 소단계, 예시, 서로 다른 활용 2개를 제공한다. 복습은 잠긴 연습 계정의 새 암호 설정·로그인·최소 권한 문서 인계다. 기존 단원과 완료 키는 유지한다. 아직 새 배포 실행파일에 포함하기 전이다.

암호는 임시 VM의 공개된 연습 계정 전용이다. 실제 passwd/PAM 질문에 입력하고 입력 문자는 표시되지 않는다. 개인 암호를 요구하거나 명령 인자로 전달하지 않는다. su와 su -의 현재 위치·HOME·로그인 설정·환경 전달을 구분하며, sudo의 인증과 정책에 따른 허가를 구분한다. sudoers를 바꾸거나 권한을 확대해서 푸는 문제가 아니다.

채점은 실제 계정·shadow 상태, 새 암호 일치, 파일 내용·소유자, 로그인 설정, 다른 계정과 보조 그룹, 로컬 sudoers 파일·권한 보존을 검사한다. 권한 보고서는 허용문 전체를 실제 조회 결과와 대조하며 줄바꿈 차이는 허용한다. 원래 learner 셸 복귀는 기존 공통 전경 프로세스 검사로 확인한다. 암호 변경 과정 자체의 모든 키 입력을 감시했다고 주장하지 않는다.

## 증분 검증

- 새 교육 계약 7개 PASS. 시뮬레이터 과정은 확장하지 않았다.
- `.jupyter-build/auth-new.json`: 새 15문제+복습 1, 오답·복구·수명 검사 7종 PASS, 47.64초. 기존 암호만 잠금 해제, 틀린 새 암호, 비로그인 환경, 허용되지 않은 sudo 명령을 거절하고 같은 실습에서 수정 가능함을 확인했다. 열린 su 셸이 있어도 다음 문제로 바꾸면 소유한 두 계정·프로세스를 정리했다.
- 감사 후 `.jupyter-build/auth-grading-delta.json`: 영향받는 sudo 활용 2번 한 문제와 변경 조건 4종 PASS, 16.62초. 전환 셸을 종료하지 않음, 거짓 추가 허용문, 다른 계정에 보조 그룹 추가, 별도 sudoers 권한 파일 추가를 각각 거절하고 복원 후 통과했다.
- 두 보고서 모두 VM 종료·임시 디스크 제거 true. 이전 소스 해시를 최신으로 바꿔 쓰지 않는다. 감사 변경과 관계없는 15문제는 반복하지 않았다.
- CPUQuota60%·nice15, 검증 동안만 절전 방지. 마지막 작업 사이 CPU 센서 41–42°C. 관측값이지 온도 상한 보장은 아니다.
