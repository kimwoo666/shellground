# APT 누락 학습 보완

Linux 전용 실제 환경에 61–65번, 5단원과 종합 복습을 추가한다. 기존 1–60번과 완료 키는 유지한다. 시뮬레이터의 명령 구현은 바꾸지 않는다. 배포 실행파일에는 아직 반영 전이다.

| 단원 | 작은 학습 범위 | 활용의 차이 |
| --- | --- | --- |
| 61 | 설치 목록과 갱신 후보 | 낡은 보고서 수정, 이미 최신인 상태 판단, 기존 보고서 백업 |
| 62 | update와 upgrade, dpkg 상태 열 | 일부만 구버전인 상태, 설정 백업 후 갱신 |
| 63 | remove와 설정 보존 | 거짓 제거 보고서와 실제 설치 상태 바로잡기, 설정 인계 |
| 64 | purge와 잔여 설정 | 이미 rc인 패키지 정리, 개인 문서와 설정 백업 구분 |
| 65 | 의존성 복구 | 빠진 의존 패키지와 너무 오래된 의존 패키지, 복구 후 상태 보고 |

각 단원은 설명을 보며 직접 실행하는 2–4개 소단계 → 예시 → 서로 다른 활용 2개로 구성한다. 활용 문제에는 명령 정답이나 채점 단축키를 넣지 않는다. 복습은 현재 사용할 note/helper 복구와 별도의 폐기 패키지(retired-note) 설정 백업·purge를 조합한다. 복구한 프로그램을 마지막에 지우지 않으므로 현재 실제 설치 상태로 복구와 정리를 모두 확인할 수 있다. retired-note는 임시 VM에서 만드는 작은 실제 deb이며 시뮬레이션 출력이 아니다.

## 실제 환경과 채점

기존 이미지에 준비된 shellground-note/helper 1.0·2.0을 재사용한다. note 2.0은 helper 2.0 이상에 의존한다. 실제 dpkg 데이터베이스, 설치 파일, conffile, 개인 문서, 다른 패키지 버전·상태를 검사한다. 낡은 상태 보고서는 실제 현재 조회 결과와 대조한다. 파일 이름이나 명령 문자열 일치로 통과시키지 않는다.

패키지 변경은 전용 VM의 임시 디스크 안에서만 수행한다. 원본 OS 이미지와 호스트 패키지는 수정하지 않는다. APT의 needrestart는 전용 게스트에서 조회 전용으로 설정하여 학습과 무관한 서비스 재시작 질문을 줄인다. 일반 Linux에서도 항상 질문이 없다는 뜻은 아니며 설명에 이 차이를 표시한다.

## 검증 기록 — 증분 검사

- 새 구조/설명/등록/채점 계약 검사 7개 통과. 기존 60단원·완료 키 및 시뮬레이터 미변경 확인.
- 최초 실제 검사: 조회 3문제 통과. 업그레이드에서 추가 서비스 질문으로 중단(73.46초), VM/임시 디스크 정리 확인. `.jupyter-build/apt-new.json`을 보존한다. 전체 통과로 표시하지 않는다.
- 서비스 질문 수정 후 변경12문제·당시 복습·오답/복구/동등9종 PASS(101.6초), VM/임시 디스크 정리 확인. `.jupyter-build/apt-mutations.json`. 기존 조회3개는 이 실행에서 반복하지 않았다.
- 감사에서 복습의 중간 복구 상태가 최종 purge로 사라지는 약점, 후보 보고서의 현재 버전 누락, 빈 후보 목록의 제목 문자열 강제를 발견했다. 복습 대상 분리·현재/후보 버전 비교·빈 후보 목록 허용을 구현했다. 변경에 해당하는 조회3문제/복습1과 오답·동등3종 **PASS(33.42초)**, VM/임시 디스크 정리 확인. `.jupyter-build/apt-grading-delta.json`.
- 최종 근거는 변경12문제의 이전 증거와 변경 후 조회3/복습1의 최신 증거를 합친 증분 검증이다. 현재 소스 전체를 다시 실행했다고 표시하지 않는다. 후보 보고서 파서 변경은 조회3개, 빈 목록 표현은 후보가 없는 조회 문제, 복습 전용 패키지는 새 복습에서 직접 확인했다. 변화 없는 업그레이드/remove/purge/의존성복구 상태 조건은 재실행하지 않았다.
- 실제 검사 CPUQuota60%/nice15, 실행 동안만 절전 방지. 확인 시 41–46°C, 임시 VM 포함 약0.85GiB cgroup 메모리. 온도와 사용량은 해당 시점 관측이지 상한 보장이 아니다.
